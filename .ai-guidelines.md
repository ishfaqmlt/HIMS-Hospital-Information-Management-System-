# Comprehensive Architectural & Style Memory Guidelines (`.ai-guidelines.md`)

This memory file contains the complete reverse-engineered style guidelines, architectural conventions, and code patterns for the **Hospital Information Management System (HIMS)** codebase. All future AI code generation, refactoring, and additions **MUST** strictly comply with these rules.

---

## 1. Executive Tech Stack & Architecture

- **Client Stack**: Next.js 16 (App Router), React 19, TypeScript/JavaScript (`.jsx` for pages/components), Redux Toolkit, Axios, `react-hook-form`, Zod validation, `shadcn/ui` (Radix UI primitives + Tailwind CSS), `lucide-react`, `react-to-print`.
- **Server Stack**: Laravel 12, PHP 8.2, Spatie Permission v6, Laravel Sanctum v4 (Bearer token-based).
- **Database**: MySQL (`db_hims`). Date format: `d-m-y` (e.g., `10-07-2026`).
- **Primary Keys**: UUID primary keys across all domain entities (`$table->uuid('id')->primary()` in migrations; `$keyType = 'string'` and `$incrementing = false` in Eloquent models).
- **Architecture Flow**:
  - `Client Request` $\rightarrow$ `AuthGuard / Axios Interceptor (Bearer Token)` $\rightarrow$ `Laravel API Route (routes/api.php)` $\rightarrow$ `auth:sanctum Middleware` $\rightarrow$ `Controller (Validation & Query Builder / Eloquent)` $\rightarrow$ `MySQL Database` $\rightarrow$ `Standardized JSON Response`.

## 2. Naming & Style Conventions

### 2.1 File & Directory Naming
- **Frontend Pages**: Must be named `page.jsx` inside PascalCase or kebab-case folder paths under `client/src/app/Modules/`.
- **Frontend Services**: Singular kebab/camel-case file names: `client/src/services/[entity].service.js` (e.g., `patient.service.js`, `billing.service.js`, `doctor.service.js`). Do **not** create plural variants like `doctors.service.js`.
- **Frontend Columns**: DataTable column definitions reside in `columns.jsx` alongside the respective `page.jsx`.
- **Backend Controllers**: `PascalCaseController.php` (e.g., `BillingController.php`, `PatientVisitController.php`).
- **Backend Models**: `PascalCase.php` (e.g., `Billing.php`, `PatientVisit.php`).
- **Backend Migrations**: `YYYY_MM_DD_HHMMSS_create_tablename_table.php` (plural snake_case table names, e.g., `create_billings_table.php`).
- **Backend Routes**: Kebab-case URL paths (e.g., `/api/doctor-share-master`, `/api/patient-payments/apply-advance`).

### 2.2 Variable & Schema Naming
- **Database Column Casing**: Primary keys are lowercase `id`. Foreign keys referencing users use `createdBy`, `updatedBy`, `postedBy` (bigint `users.id`). Foreign keys referencing domain UUIDs use `visitId`, `departmentId`, `doctorId`.
- **Model Attribute Casing**: Match migration column names explicitly.
- **Redux Slice Names**: Plural nouns for slice state keys (e.g., `doctors`, `departments`, `masterTests`, `billingData`). Use `list` as the array property name within slice state (`state.list = action.payload`).

## 3. Backend Guidelines (Laravel 12)

### 3.1 Authentication & Permissions
- **Sanctum Authentication**: Pure token-based Bearer authentication (`HasApiTokens`). Cookie-based stateful authentication is completely disabled.
- **Token Handling**: Login/Register issues plain-text token (`$user->createToken('auth-token')->plainTextToken`). Logout revokes current token (`$request->user()->currentAccessToken()->delete()`).
- **Roles & Permissions**: Models use Spatie `HasRoles`. `super_admin` possesses wildcard (`*`) access in permission evaluation payloads.

### 3.2 Routing & Controller Standards
- **Route File**: All backend API endpoints reside in `server/routes/api.php`.
- **Route Protection**: Wrap all domain endpoints inside `Route::middleware('auth:sanctum')`.
- **Validation**: Perform validation inline within controllers using `$request->validate([...])`.
- **Standard HTTP Responses**:
  - `201 Created`: Returned on creation (`store`, `bulkStore`).
  - `200 OK`: Returned on reads (`index`, `show`), updates (`update`), and deletes (`destroy`).
  - `404 Not Found`: Return `response()->json(['message' => 'Resource not found'], 404)` when entity is missing.
  - `500 Internal Server Error`: Return `response()->json(['message' => 'Operation failed: ' . $e->getMessage()], 500)` inside catch blocks.

### 3.3 Database Operations (`DB::table()` vs Eloquent)
- **Data Mutation (Store / Update)**: ALWAYS use `DB::table('table_name')->insert($data)` and `DB::table('table_name')->where('id', $id)->update($data)` for store and update operations in financial and transactional modules.
  > *Rationale*: Eloquent's dirty attribute detection silently skips updates when casting `decimal` fields if PHP float comparisons evaluate as unchanged.
- **Read Queries & Joins**: Use `DB::table('table_name')` with explicit `leftJoin()`s for financial, billing, and lab queries where foreign keys reference string IDs (e.g., `patient_visits.patientId` storing `pid-MMYY-###`).
  > *Rationale*: Avoids Eloquent eager-loading crashes caused by UUID-to-string type mismatches.
- **Simple Master CRUD**: Pure Eloquent is permitted for isolated lookup tables (e.g., `FloorMaster`, `Department`).

### 3.4 Database Transactions & Performance
- **Mandatory Transactions**: Any controller method performing multiple database mutations MUST wrap execution in `DB::beginTransaction()`, `DB::commit()`, and `DB::rollBack()` inside `try/catch`.
- **N+1 Prevention**: NEVER query the database inside array map or foreach loops. Pre-fetch child collections using `whereIn('parent_id', $parentIds)` or SQL joins prior to loop iterations.

## 4. Frontend Guidelines (Next.js 16 & React)

### 4.1 Layout & Navigation
- **Module Wrapper**: All `/app/Modules/` pages are wrapped in `ModulesLayout`, enforcing `<AuthGuard>` authentication and displaying the top `<Navbar />`.
- **No Sidebars**: Main module pages use full-screen width (`flex-1 p-6`) without sidebars to maximize screen space for dense medical data tables and forms.
- **Root Route**: `app/page.tsx` performs immediate client redirect to `/login`.

### 4.2 Form Handling (`react-hook-form` + Zod)
- **Schema Centralization**: ALL Zod validation schemas MUST be defined in `@/lib/zodeSchema.js`.
- **Form Pattern**:
  ```jsx
  import { useForm } from "react-hook-form";
  import { zodResolver } from "@hookform/resolvers/zod";
  import { mySchema } from "@/lib/zodeSchema";

  const { register, handleSubmit, formState: { errors } } = useForm({
    resolver: zodResolver(mySchema),
  });
  ```
- **Controlled Components**: Use `<Controller>` or `setValue()` for custom UI selectors (e.g., shadcn `<Select>`).
- **No Manual Form State**: Never create manual `useState` hooks for individual form input fields.
- **Error Display**: Display field errors directly beneath inputs:
  `<p className="text-xs text-destructive mt-1">{errors.fieldName.message}</p>`

### 4.3 Service Layer Pattern
- **Axios Singleton**: Import shared axios instance: `import axios from "@/lib/axios";`.
- **Service Export**: Export object with named function methods returning raw Axios Promises.
  ```js
  import axios from "@/lib/axios";

  const patientService = {
    getAll: (params) => axios.get("/patients", { params }),
    getById: (id) => axios.get(`/patients/${id}`),
    create: (data) => axios.post("/patients", data),
    update: (id, data) => axios.put(`/patients/${id}`, data),
    delete: (id) => axios.delete(`/patients/${id}`),
  };

  export default patientService;
  ```

### 4.4 UI Components & Data Table
- **shadcn/ui Enforcement**: ALL UI elements MUST be imported from `@/components/ui/` (`Button`, `Input`, `Select`, `Dialog`, `Card`, `Badge`, `Table`, etc.). Direct HTML `<button>` or `<input>` elements are strictly prohibited.
- **Icons**: Import exclusively from `lucide-react`.
- **DataTable Architecture**:
  - `columns.jsx`: Exports `getColumns()` returning TanStack table column definitions.
  - `page.jsx`: Invokes `<DataTable columns={columns} data={items} filterColumn="columnId" />`. Note: `filterColumn` MUST match column `id` or `accessorKey`.

## 5. Specialized Domain Rules

### 5.1 Patient Identification & Masking
- **Sequence Formats**:
  - Patient ID: `pid-{MMYY}-{SEQ}` (e.g., `pid-0726-001`)
  - MRN: `mrn-{MMYY}-{SEQ}` (e.g., `mrn-0726-001`)
  - Invoice No: `INV-{MMYY}-{SEQ}` (e.g., `INV-0726-001`)
- **Input Masking**: Use `formatCode(val)` utility on MRN/Patient ID inputs to auto-strip non-digits and insert dash after 4th digit (e.g., `0726001` $\rightarrow$ `0726-001`).

### 5.2 Billing Module Layout & Logic
- **Three-Column Grid**: Left (Department & Service selection) | Center (Selected Services Table) | Right (Totals, Discounts, Payment details).
- **Service Flagging**: New services flagged `I` (can be deleted); loaded existing invoice services flagged `U` (cannot be deleted).
- **Net Amount & Paid Default**: `paid` amount defaults to `netAmount` whenever line items or discounts change.

### 5.3 Printing & Reports
- **react-to-print**: Uses `useReactToPrint` hook referencing layout components in `app/Modules/Reports/Reception/`.
- **Formats Supported**: Thermal 80mm receipt (`ThermalPrintLayout.jsx`) and A4 invoice (`A4PrintLayout.jsx`).

## 6. Strict Development & Migration Rules

1. **Migration Safety**: NEVER run `migrate:fresh`. When altering tables, create a new migration AND update the original `create_*_table` migration. Once applied, remove the alter migration file so schema changes remain consolidated in main migrations.
2. **FK Type Matching**: Ensure FK definitions match target column types. If target is non-UUID string, perform raw `DB::table()` queries instead of declaring Eloquent relation constraints.
3. **No Alien Code Paradigms**: Write all new modules, endpoints, schemas, and UI views to perfectly match the patterns established in this file and `AGENTS.md`.
